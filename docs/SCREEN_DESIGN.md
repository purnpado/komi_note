# 꼬미노트 화면 설계 기준

> 상태: 화면 구조의 기준 문서입니다.

## 설계 원칙

- 개인정보가 포함된 화면은 프로그램 잠금 해제 뒤에만 표시한다.
- 한 화면에서 판단하고 바로 기록할 수 있도록 오늘 업무와 학생 상태를 우선 배치한다.
- 모든 입력 기능은 저장 전 확인, 변경 이력, 암호화 백업을 기본으로 한다.

## 화면 흐름

1. 잠금 화면: 마스터 비밀번호와 학년도·학반을 확인한다. 최초 실행 시 비밀번호와 학반을 설정한다.
2. 대시보드: 오늘 일정, 반 시간표·교사 시간표, 출결, 상담 후속 조치, 기록 작성 현황을 한 화면에 보여 준다.
3. 학생 명렬: 나이스 엑셀·CSV를 미리보기와 열 연결 확인 뒤 가져온다. 학생을 선택하면 **학생 상세정보**에서 기본 정보와 상담·출결·평가를 확인한다.
4. 상담 기록: 학생별 누적 기록과 후속 조치 예정일을 관리한다.
5. 출결 관리: 일별 출결을 입력하고 등록한 결석계 PDF·HWPX 양식에 정보를 채운다.
6. 학급 운영: 자리배치, 청소구역, 당번을 만들고 인쇄한다.
7. 평가 관리: 수행평가 항목·배점·점수·관찰 메모와 공개 상태를 관리한다.
8. 학교생활기록: 교과세특·창체·행동특성(담임만)·자유학기제의 관찰 메모와 기재 문장을 쓴다(2026-11-09 1단계 구현). 학생 이름 없는 문장 자산 보관함은 다음 단계에서 만든다.
9. 예산 관리: 예산, 지출, 증빙, 잔액과 보고서를 관리한다.

## 초기 데이터 경계

- 학생과 상담 기록은 로컬 암호화 데이터베이스와 암호화 첨부파일에만 저장한다.
- 구글 캘린더 연결은 교사가 선택하며, 기본 일정 제목에는 학생 이름을 넣지 않는다.
- 학생 개별 성적 조회는 별도 읽기 전용 서비스로 분리해 후속 단계에서 구현한다.
