# 꼬미노트

> 마지막 기능 문서 현행화: 2026-11-08

중등교사를 위한 Windows 독립 실행형 교사 업무공간입니다. 학생 개인정보를 기본적으로 교사 컴퓨터에만 저장하는 것을 원칙으로 합니다.

## 프로젝트 아키텍처 및 패키지 구조

본 프로젝트는 클린 아키텍처 원칙에 따라 루트의 모놀리스 구조를 도메인별 `internal/` 패키지로 완전 분리하여 유지보수성과 보안성을 극대화했습니다.

```
TeacherNote/
├── main.go                     # 프로그램 진입점 및 Wails v3 데스크톱 앱 생명주기 제어
├── app.go                      # 프론트엔드 Wails v3 바인딩 어댑터 (타입 알리아스 및 API 노출)
├── e2e_scenario_test.go        # 보관함 생성~학급운영~잠금/해제 전체 라이프사이클 E2E 통합 검증
├── seed_vault_test.go          # 화면 실측용 가상 25명 학급 생성기 (KKOMI_SEED_SAMPLE=1일 때만 실행)
├── assessment_confirmation_test.go # 수행평가 이의 처리 및 나이스 서식 파싱 검증
├── internal/
│   ├── vault/                  # 중앙 암호화 보관함 (Argon2id, AES-256-GCM, 순환 백업)
│   ├── students/               # 학생 명렬 관리 및 만 나이/성별 통계 도메인
│   ├── attendance/             # 출결 관리, HWPX 치환자 생성 및 PDF 서식 인쇄
│   ├── seating/                # 자리배정 엔진 (룰렛, 사다리, 희망경쟁) 및 QR 참여 웹 서버
│   ├── assessment/             # 수행평가 도메인, 나이스 엑셀 파서, 실시간 확인 웹 서버 및 이벤트 버스
│   ├── survey/                 # 학급 설문 엔진 및 교실 실시간 참여 웹 서버
│   ├── submissions/            # 현장체험학습 등 제출서류 수합 도메인
│   ├── cleaning/               # 청소구역 자동/수동 편성 및 점검 도메인
│   └── system/                 # 네트워크 주소 탐지, 안전한 파일 동기화(fsync), 메모리 소거(ZeroBytes), Windows DPAPI PIN 보호, 업데이트 정보 ed25519 서명·파일 SHA-256 확인
├── cmd/                        # 검수용 가상 파일 생성기(수행평가·명렬표), 아이콘 변환, 업데이트 서명 도구(sign_update)
├── docs/                       # 개발 계획·작업 기록·인수인계·상세 설계 문서
└── frontend/                   # React + TypeScript + Radix UI, 기능별 CSS 프론트엔드 (Vite)
```

## 현재 구현된 기능

- 수업 명렬의 학생 추가·번호/이름 수정·재학/전출 변경과 확인 후 명렬 삭제, 이름 없는 변경 이력

- 수업 명렬 학년도·학년별 학급 선택과 수행평가 점수표 안의 영역별 학생 확인 상태

- 기존 수행평가에서 학생 명렬을 비교한 뒤 수업 명렬로 보내기

- 나이스 수행평가 파일명의 학년을 확인·수정하고 평가 목록을 학년별로 접고 펼치기

- 수행평가 영역별 학생 확인·이의 현황을 교사 화면에 표시하며 기존 영역 미기록 이력은 별도로 안내

- 최초 실행 시 학교·학반·자동 잠금 시간 설정
- 마스터 비밀번호 및 간편 숫자 PIN 이중 암호화 보관함 (Argon2id + AES-256-GCM)
- 일상 업무 및 자동 잠금 해제용 간편 숫자 PIN 번호(4~8자리) 로그인 지원
- 간편 PIN은 Windows DPAPI로 등록한 PC의 같은 Windows 계정에서만 작동하며, 프로그램 폴더를 다른 PC·계정으로 옮기면 마스터 비밀번호 로그인과 PIN 재등록을 안내
- PIN 연속 5회 오류 시 간편 로그인 자동 잠금 및 마스터 비밀번호 강제 전환 (무차별 대입 방어, 프로그램을 다시 켜도 횟수 유지)
- 외부 저장 복구 파일과 복구용 암호를 통한 비밀번호 재설정
- 화면 잠금과 기본 5분 자동 잠금, 환경 설정에서 잠금 시간 및 간편 PIN 변경/삭제
- QR 참여 회차 중에는 자동 잠금을 미루되, 마지막 입력 뒤 30분이 지나면 잠금(QR 회차는 일시정지)
- 자리배정·설문·수행평가 QR 화면에 교실 와이파이 안내 표시(학생 주소는 암호화되지 않은 http이므로 업무망·교실 전용 와이파이에서 열고 끝나면 닫기)
- 최소화·최대화/복원·전체화면·닫기 버튼이 있는 맞춤 제목 표시줄
- 모니터 작업 영역에 맞춘 최대화 시작과 창 크기별 반응형 화면
- 오늘의 교사 업무 대시보드와 수업용 수행평가 관리
- 대시보드·환경 설정을 포함한 메뉴별 React 기능 모듈 분리
- 왼쪽 메뉴 전체와 메뉴 그룹·학급 운영 하위 목록 접기 및 펼치기
- 환경 설정의 역할·자동 잠금·학사 일정 안내 및 테마 견본 제공
- 학생 전입일 기록과 전출·유예·자퇴·면제·정원외·조기졸업 학적변동 처리
- 학적변동 시 학생 개인정보·사진·상담 기록 삭제와 이름·종류·처리일 최소 이력 보관
- 일별 재학생 출결 입력과 결석·지각·조퇴·결과 사유 구분 암호화 저장
- 학교별 HWPX 출결 서식의 치환자 기반 단일·연속 건 개별 생성(`{{보호자성명}}` 포함)과 기존 PDF 좌표 출력
- 학급 운영의 자리배정: 이전 배치 이력, 격자형·사용자 지정 교실 배치도 설정, QR 학생 입장, 랜덤 룰렛·랜덤 사다리·희망 경쟁 가위바위보, 전자칠판, 최종 자리표 가로 인쇄
- 학급 운영의 청소구역 배정: 주간·격주·월간·직접 지정 기간의 구역별 수동 편성, 중복·인원·직전 담당·미경험 구역 점검, 이력과 인쇄
- 수업용 수행평가: 나이스 수행평가 파일일괄등록 엑셀의 과목·반·번호·성명·영역 총점을 수업 최소 명렬과 함께 암호화 저장, 영역별 교사용 세부 기준·점수·학생별 채점 사유 입력, 영역별 학생 QR·별도 전자칠판, 학생 본인 확인·이의 제출·교사 답변·답변 재확인 QR·답변 완료 이의 삭제, 전용 Radix 확인·입력 창

나이스 엑셀 명렬표를 미리 확인한 뒤 번호·성명·성별·생년월일·주소를 암호화 보관함에 저장하고, 학생별 연락처와 부·모·기타 보호자 성명을 직접 보완할 수 있습니다. 잠금 해제 뒤 `학생 통계`에서 오늘 또는 선택 기준일의 만 나이·성별 통계를 확인할 수 있습니다. 수행평가를 가져올 때 학년도·학년·반을 확인해 새 수업 명렬을 암호화 저장하고, 같은 반의 기존 명렬과 다르면 차이를 안내하고 자동 변경하지 않습니다. 평가별 최소 명렬과 점수는 별도로 유지합니다. 나이스 원본 영역 총점은 참고용으로 보관하고, 과거 임시 `영역 점수` 열은 즉시 숨기며 다음 저장 때 참고값으로 이전합니다. 세부 기준 점수는 전체 점수 저장으로, 채점 사유는 대화상자의 `사유 저장`으로 해당 학생·기준만 즉시 저장합니다. 나이스 수행평가 파일은 반별로 하나씩 가져올 수 있으며, 파일의 반이 환경설정 수업 학반 목록에 없더라도 안내를 확인한 뒤 해당 파일의 반으로 등록할 수 있습니다. 학생 QR 확인은 교사가 연 교실 내부 임시 주소에서만 가능하며, 점수·채점 사유·이의 내용은 전자칠판이나 다른 학생에게 공개하지 않습니다.
대시보드와 학교생활기록·예산 관리는 예시 또는 안내 화면이며, 해당 화면의 수치가 실제 보관함 자료와 연동된 것은 아닙니다. 프론트엔드 스타일은 `frontend/src/features/<기능>/` 아래 기능별 CSS로 대부분 분리했습니다. `App.css`에는 테마·대화상자·잠금 화면·앱 셸 같은 공통 스타일과 아직 옮기지 않은 일부 설정·출결·상담 규칙이 남아 있습니다.

암호화 보관함은 실행 파일과 같은 폴더의 `data\vault.dat`에 저장됩니다. 실행 파일을 옮길 때는 `data` 폴더도 반드시 함께 옮겨야 합니다. 이전 버전의 Windows 설정 폴더 보관함은 첫 실행 때 자동으로 `data` 폴더로 이전합니다.

한글·공백·일반 기호가 포함된 프로그램 폴더와 명렬표 파일 경로를 지원합니다.

학생 명렬은 그리드형 카드 뷰와 테이블 목록 뷰를 지원하며, 학생 사진, 성별, 만 나이, 연락처 상태, 지도 유의사항 및 특이사항 배지를 직관적으로 확인할 수 있습니다. 학생 카드를 누르면 `학생 상세정보`가 열립니다. 학생별 사진은 JPG·PNG·WEBP 파일을 직접 선택해 암호화 저장할 수 있고(암호문이 학생 ID에 묶여 다른 학생 사진 파일로 바꿔 넣으면 열리지 않음), 학생 기본 정보·특이사항(Note)·보호자 연락처·상담 누적 기록을 한 화면에서 체계적으로 관리하고 수정할 수 있습니다. 학생 명렬 초기화는 확인 문구를 입력한 경우에만 학생 정보·사진·상담 기록을 삭제하며, 학급 기본 설정과 복구 파일은 유지합니다.

자리배정은 세 가지 게임 모듈(랜덤 룰렛·랜덤 사다리·희망 경쟁 가위바위보)로 구성됩니다. 전자칠판과 학생 휴대폰 화면은 각각 한 장의 화면이 진행 단계에 따라 바뀌며, 전자칠판은 16:9 무대를 화면 크기에 맞춰 확대·축소하고 학생 수에 따라 칸·글자 크기를 자동으로 조절합니다. 랜덤 룰렛은 입장 마감 뒤 순서 섞기(전자칠판 슬롯과 순서판, 학생 휴대폰에 "내 순서 N번째")를 거쳐, 자기 차례의 학생이 휴대폰에서 [룰렛 돌리기]를 누르면 전자칠판 룰렛이 돌아갑니다. 전자칠판 왼쪽에는 배정 순서 진행표, 가운데에는 지금 차례와 남은 시간이 들어간 룰렛, 오른쪽에는 확정 자리가 채워지는 교실 배치도가 보입니다. 마지막 한 명은 남은 유일한 자리로 자동 확정합니다. 랜덤 사다리는 같은 방식으로 순서를 정한 뒤 학생이 남은 출발점 번호 하나를 고르고, 모두 고르면 교사가 사다리를 공개해 한 명씩 경로를 보여 줍니다. 희망 경쟁은 학생이 휴대폰 배치도에서 1~3지망 자리를 눌러 제출하고, 단독 후보는 즉시 확정, 복수 후보는 세로형 토너먼트 대진표의 가위바위보로 정합니다. 진행 중 전자칠판과 학생 화면에는 닉네임만 표시하고, 최종 자리배치에서만 전자칠판에 실명을 표시합니다. 학생 휴대폰은 배정 뒤 내 자리 번호와 위치만 표시합니다. 고정 자리는 교사만 알 수 있도록 랜덤 룰렛·랜덤 사다리에만 적용합니다. 프로그램 안 배치도는 창 높이에 맞춰 책상 크기를 조절해 학생 수와 상관없이 한 화면에 들어오며, 모둠형은 모둠을 교실처럼 2차원으로 배치합니다.

## 실행 파일 만들기

Wails v3.1.0 기반으로 구축되어 macOS, Linux, Windows 환경 모두에서 CGO 없이 순수 Go로 Windows용 실행 파일(.exe) 크로스 컴파일 및 macOS 앱 빌드가 가능합니다.

```bash
# Windows용 단독 실행 파일 (.exe) 빌드
wails3 build GOOS=windows ARCH=amd64

# macOS용 앱 번들 (.app) 빌드 및 패키징
wails3 task package
```

완성된 파일은 `bin/꼬미노트.exe` 및 `bin/꼬미노트.app`에 생성됩니다.

## 개발 검사

```bash
go vet ./...
go test -race ./...
cd frontend && npx tsc --noEmit && npm run build
# 맥북 Node 22.14에서는 옵션이 필요합니다.
node --experimental-strip-types --test src/features/assessment/assessmentState.test.mjs
```

- `go test ./...`은 `bin/data/vault.dat`를 건드리지 않습니다. 가상 25명 보관함이 필요할 때만 `KKOMI_SEED_SAMPLE=1 go test -run TestSeedSampleData .`을 실행합니다. 실제 보관함이 있는 폴더에서는 실행하지 않습니다.
- 브라우저로 화면을 확인할 때는 `go build -tags server -o bin/꼬미노트-server .`로 만든 뒤 `WAILS_SERVER_HOST=127.0.0.1 WAILS_SERVER_PORT=18800`을 지정해 실행합니다. (`wails3 task build:server DEV=true`로도 만들 수 있습니다.)
- 자리배정 전자칠판·학생 화면은 `internal/seating/public/board.html`, `student.html`이며 `go build` 때 실행 파일에 포함됩니다.

## 업데이트와 릴리즈

실행 파일은 이 저장소의 [릴리즈](https://github.com/purnpado/komi_note/releases)에서 내려받습니다. 기존 프로그램 폴더의 실행 파일만 교체하고, 같은 폴더의 `data` 폴더(학생 데이터)는 옮기거나 삭제하지 않습니다.

프로그램은 최신 릴리즈의 `latest.json`을 읽어 새 버전을 확인합니다. `latest.json`의 ed25519 서명이 실행 파일에 내장된 공개키(`internal/system/update_signature.go`)와 맞고, 내려받은 exe의 SHA-256이 일치할 때만 교체합니다. 서명용 개인키는 저장소에 포함하지 않으며, 배포 담당자가 `cmd/sign_update`로 서명합니다. 학생 정보·암호화 보관함·개인 토큰은 전송하거나 포함하지 않습니다.

## 직접 수정해서 배포하려면 (포크 안내)

이 프로그램을 쓰기만 할 때는 서명키가 필요 없습니다. 아래 내용은 소스를 고쳐 **자기 이름으로 배포**하려는 개발자를 위한 안내입니다.

업데이트 서명용 개인키는 원 배포자만 가지고 있으며 이 저장소에 없습니다. 그래서 수정본은 자기 키와 자기 릴리즈 주소를 써야 합니다. 그렇지 않으면 업데이트 확인에서 서명이 맞지 않아 업데이트가 거부됩니다.

1. 서명키를 만듭니다. 개인키는 저장소 **밖**에 저장하고 절대 커밋하지 않습니다(`.gitignore`에 `*.key`가 들어 있습니다).
   ```
   go run ./cmd/sign_update genkey -out ~/.config/my-app/update-signing.key
   ```
   화면에 나온 공개키를 `internal/system/update_signature.go`의 `UpdatePublicKey`에 넣습니다.
2. 업데이트 주소를 자기 저장소로 바꿉니다.
   - `internal/system/version.go`의 `UpdateManifestURL` → `https://github.com/<계정>/<저장소>/releases/latest/download/latest.json`
   - `internal/system/updater.go`의 `updateDownloadPrefix` → `https://github.com/<계정>/<저장소>/releases/download/`
3. 앱 식별 정보를 바꿉니다. `build/config.yml`의 `companyName`, `productIdentifier`, `copyright`, `build/darwin/Info.plist`, `wails.json`의 작성자를 바꿉니다.
4. 버전(`internal/system/version.go`의 `AppVersion`)을 올리고 Windows용으로 빌드합니다(위 "실행 파일 만들기").
5. 릴리즈 정보에 서명합니다.
   ```
   go run ./cmd/sign_update sign -key ~/.config/my-app/update-signing.key \
     -manifest dist/latest.json -exe bin/꼬미노트.exe -version <버전> -now \
     -notes "변경 내용" -url https://github.com/<계정>/<저장소>/releases/download/v<버전>/kkomi-note.exe
   ```
6. GitHub 릴리즈(태그 `v<버전>`)에 실행 파일을 `kkomi-note.exe`라는 이름으로 바꿔 올리고, 함께 `latest.json`을 올립니다. **Pre-release로 표시하지 않습니다.** Pre-release로 표시하면 `latest` 주소에 잡히지 않습니다.

업데이트 기능이 필요 없으면 `internal/system/version.go`의 `UpdateManifestURL`을 빈 문자열(`""`)로 두세요. 그러면 프로그램이 "업데이트 채널이 설정되지 않았습니다"라고만 안내하고, 업데이트를 확인하거나 내려받지 않습니다.

## 개인정보 보호 원칙

- 실제 학생 데이터와 백업 파일은 Git에 올리지 않습니다.
- 가져온 엑셀·CSV·한글 명렬표도 기본적으로 Git에서 제외합니다.
- 복구 파일은 프로그램 데이터와 다른 외부 저장 위치에 보관합니다.
- 암호화 보관함은 마스터 비밀번호를 저장하지 않고, 암호 키로 보호합니다.
- `학생명렬표_가상25명.xlsx`는 가져오기 기능을 검증하기 위한 25명 가상 자료이며 Git에 올리지 않습니다.
- 수행평가 가져오기 검수용 가상 파일은 `go run ./cmd/assessment_fixture -output C:\tmp\수행평가_가상6명.xlsx`로 필요할 때만 생성합니다. 생성 파일에는 가상 이름·점수만 들어가며 Git에 올리지 않습니다.
